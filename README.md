# کلمه‌باز 🧩

ربات بازی گروهی حدس کلمه با حروف فارسی (شبیه آمیرزا) برای تلگرام. Python + aiogram 3 + PostgreSQL.
تعامل اصلی با **کلمات کلیدی فارسی** است («شروع بازی»، «برترین‌ها»، …) و حدس‌ها فقط با نوشتن خود کلمه در گروه ثبت می‌شوند.

## دستورات (بدون اسلش)

| عبارت | کار | دسترسی |
|---|---|---|
| شروع بازی / بازی شروع | شروع مرحله | همه یا فقط مدیران (تنظیمات) |
| توقف بازی | توقف | مدیران |
| مرحله بعد / بازی بعدی | مرحله بعد | مدیران |
| راهنمای بازی | راهنما | همه |
| امتیاز من | آمار شخصی (امروز/هفته/ماه، رتبه گروه و جهانی) | همه |
| برترین‌ها | جدول گروه | همه |
| رتبه جهانی | جدول سراسری | همه |
| آمار بازی / وضعیت بازی | آمار گروه / مرحله فعلی | همه |
| تنظیمات بازی | منوی تنظیمات دکمه‌ای | مدیران |
| پیشنهاد کلمه X | پیشنهاد واژه (حداکثر ۵ در روز) | همه |
| پنل مدیریت (چت خصوصی) | پنل مالک | فقط OWNER_ID |

مقایسه‌ی عبارت‌ها بعد از نرمال‌سازی است: ی/ي، ک/ك، فاصله‌ی اضافی و نیم‌فاصله فرقی نمی‌کنند. کلمات مدیریتی **قبل از** بررسی جواب‌ها پردازش می‌شوند و جواب‌ها هرگز با آن‌ها تداخل ندارند. `/start` فقط در چت خصوصی کار می‌کند.

## راه‌اندازی تلگرام (مهم)

1. در BotFather: `/newbot` و گرفتن توکن.
2. **Privacy Mode:** برای دیدن پیام‌های عادی گروه یکی از این دو کار لازم است:
   - ربات را در گروه **مدیر** کنید (ساده‌تر و بدون نیاز به BotFather)، یا
   - BotFather ← `/setprivacy` ← ربات ← **Disable**. بعد از تغییر باید ربات را **از گروه حذف و دوباره اضافه کنید** تا اعمال شود.
   - اگر هیچ‌کدام انجام نشده باشد، ربات خودش به گروه هشدار می‌دهد.
3. شناسه‌ی عددی خودتان را از @userinfobot بگیرید و در `OWNER_ID` بگذارید.

## اجرا روی رندر (رایگان)

محدودیت‌های واقعی پلن رایگان:
- بعد از ۱۵ دقیقه بدون ترافیک سرویس می‌خوابد و بیدارشدنش حدود ۱ دقیقه طول می‌کشد. چون ربات **webhook** است، پیام‌های گروه خودشان سرویس را بیدار می‌کنند؛ حالت خواب فقط در ساعت‌های بی‌فعالیت پیش می‌آید. برای «شروع خودکار مرحله بعد» در حالت بی‌فعالیت، یک پینگر رایگان (مثل UptimeRobot) روی `https://<app>.onrender.com/healthz` هر ۵ دقیقه بگذارید.
- Postgres رایگان رندر **۳۰ روز بعد منقضی می‌شود** و پشتیبان ندارد. پیشنهاد: Postgres رایگان بیرونی (Neon/Supabase؛ محدودیت‌های فعلی‌شان را بررسی کنید) و گذاشتن آدرسش در `DATABASE_URL`.
- ۵۱۲ مگابایت رم و ۰٫۱ CPU: طراحی بر همین اساس است (کل بانک در رم نیست و ایندکس در دیتابیس است).

مراحل: مخزن را در گیت‌هاب بگذارید ← Render: New → Blueprint (یا Web Service با Docker) ← متغیرهای `BOT_TOKEN`، `OWNER_ID`، `DATABASE_URL` را وارد کنید. `RENDER_EXTERNAL_URL` خودکار خوانده می‌شود و webhook خودش ثبت می‌شود. حتماً **فقط یک نمونه** از ربات اجرا شود.

## اجرای محلی / VPS

```bash
cp .env.example .env      # مقادیر را پر کنید
docker compose up -d --build
```
بدون داکر: `pip install -r requirements.txt` و `MODE=polling python -m app.main`.

## بانک واژگان

با اولین اجرا یک **بانک اولیه‌ی کوچک** (حدود ۴۵۰ کلمه‌ی دستچین، `data/seed_words.txt`) وارد می‌شود تا بازی فوراً کار کند. برای بازی واقعی باید بانک بزرگ وارد کنید:

```bash
export DATABASE_URL=...
python -m app.words.importer add lexicon.txt --source persian-lexicon     # کلمات معتبر (همه‌چیز می‌تواند کلمه‌ی اضافی باشد)
python -m app.words.importer freq freq.txt --source corpus                 # فایل «کلمه تعداد» از پیکره‌ی متنی
python -m app.words.importer recompute --min-freq 50                       # سختی ۱ تا ۵ از چندک بسامد + انتخاب کلمات مناسب معما
python -m app.words.importer stats
```
یا فایل را در چت خصوصی برای ربات بفرستید (مالک). فرمت‌ها: TXT (کلمه یا «کلمه ۱۲۳»؛ خطوط `#difficulty=2` و `#category=literary`)، CSV (`word,freq,category,difficulty,puzzle_ok,bonus_ok`)، JSON.

**کلمه‌ی معتبر ≠ کلمه‌ی مناسب معما:** همه‌ی واژه‌های معتبر می‌توانند کلمه‌ی اضافی باشند، ولی جواب اصلی فقط از واژه‌های `puzzle_ok` (۳ تا ۸ حرف و رایج) انتخاب می‌شود. بدون فایل بسامد، کلمات import‌شده فقط کلمه‌ی اضافی‌اند مگر `--trust-puzzle` بدهید.

منابع پیشنهادی (مجوز هرکدام را قبل از استفاده بررسی کنید): واژه‌نامه‌ی Hunspell/Aspell فارسی (حدود ۳۰۰ هزار مدخل، شامل شکل‌های صرف‌شده)، persian-lexicon (حدود ۷۰ هزار، MIT)، لیست Virastyar در Hazm، ویکی‌واژه فارسی (CC BY-SA)، و پیکره‌هایی مثل Jomleh/naab فقط برای شمارش بسامد. این پروژه کلمه‌ی ساختگی تولید نمی‌کند؛ تعداد واقعی مدخل‌ها را `stats` یا پنل مالک نشان می‌دهد.

## نحوه‌ی کار

- هر مرحله: یک کلمه‌ی پایه (۴ تا ۸ حرف) با سختی مناسب انتخاب می‌شود؛ همه‌ی کلمات قابل‌ساخت با **ایندکس امضای حروف** (`letters_sig`) از دیتابیس خوانده می‌شوند، نه با اسکن کل بانک.
- ضدتکرار: کلمه‌ی پایه‌ی ۳۰۰ مرحله‌ی اخیر و جواب‌های اصلی ۱۵۰ مرحله‌ی اخیر **همان گروه** دوباره انتخاب نمی‌شوند (فقط اگر بانک کوچک باشد، محدودیت نرم می‌شود).
- ثبت جواب اتمیک است: `UPDATE ... WHERE found_by IS NULL` در یک تراکنش؛ فقط اولین نفر برنده می‌شود.
- زمان پایان در دیتابیس ذخیره می‌شود و بعد از ری‌استارت بازیابی می‌شود. پیام مرحله با حداقل ۲ ثانیه فاصله ویرایش می‌شود.
- حدس اشتباه و پیام عادی بی‌پاسخ می‌ماند و کوئری دیتابیس نمی‌زند.
- دکمه‌ها از فیلد رسمی `style` (آبی `primary`، سبز `success`، قرمز `danger`) استفاده می‌کنند؛ کلاینت‌های قدیمی بدون رنگ نشان می‌دهند. با `BUTTON_STYLES=false` خاموش می‌شود.

## تست

```bash
python -m unittest discover -s tests -v
```
تست‌ها منطق خالص (نرمال‌سازی، کلمات کلیدی، تولید مرحله، امتیاز، نمایش، ایمپورت، بازه‌های زمانی) را پوشش می‌دهند. لایه‌ی دیتابیس و تلگرام نیاز به تست دودی (smoke test) با توکن و Postgres واقعی دارد.

## محدودیت‌های شناخته‌شده

- فقط یک نمونه‌ی ربات (وضعیت مراحل فعال در حافظه هم کش می‌شود).
- «شروع خودکار مرحله بعد» اگر سرویس رایگان خوابیده باشد تا بیدارشدن عقب می‌افتد.
- ماه در گزارش‌های دوره‌ای میلادی است؛ هفته از شنبه شروع می‌شود.
- حرف «آ» با «ا» یکسان فرض نمی‌شود.
